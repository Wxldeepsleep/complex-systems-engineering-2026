选题与系统定义 为什么是线控底盘

定义System of Interest

面向 L4 级高级别自动驾驶的线控底盘平台，以电信号为指令载体，通过冗余架构实现制动、转向、驱动、悬架等运动控制，向上承接智驾域规划决策指令，向下驱动各执行部件，是连接「大脑决策」与「车轮执行」的关键环节。

其本质是高阶智驾的「最后一公里执行机构」：上层给出纵向加减速、横向转角与姿态目标，底盘实时、精确、安全地转化为车轮与路面的力与运动。

边界内

线控制动、线控转向、线控驱动 / 扭矩控制、主动悬架与姿态、底盘域控制器、功能安全与冗余监控链路。

边界外

感知 / 决策规划算法、车身内外饰与乘员舱、动力三电与电池能源、车路云协同与交通基础设施；仅通过标准车载接口交互。

Part 2 · 作业 1 层级分解

上层要素：任务 · 体系 · 整机

Mission任务层

  • 安全出行运输：城市 / 高速 / 园区内可靠完成人员运输与配送
  • 高阶智驾落地：无人工接管条件下连续稳定运行
  • 全域运动操控：精确完成加减速、转向、制动、平顺性调节
  • 失效兜底：任一链路失效仍可降级行驶或安全停车
  • 节能与舒适：降低能耗、提升平顺性与乘坐品质

SoS体系层

  • 自动驾驶整车系统族：乘用车 / Robotaxi / 物流车共享平台
  • 感知—决策—规划系统：摄像头 / 雷达 / 高精地图 / 域控
  • 动力与能源系统：三电、能量与热管理
  • 车身与座舱系统：结构、乘员舱、被动安全
  • 车路云协同：V2X、云控调度、OTA 与远程诊断

Vehicles整机层

  • 自动驾驶乘用车：城市道路与高速场景
  • Robotaxi 无人出租车：对冗余与可靠性要求最高
  • 自动驾驶物流车 / 卡车：大载荷、长续航
  • 集成要素：轴距 / 轮距、整车质量、轴荷分配、离地间隙、安装接口与布置空间

SoS 关键特征：各成员系统原本可独立运行、独立演进，通过标准化接口耦合为整体；高阶自动驾驶这一整体能力无法由任一成员单独实现，属于涌现能力（Emergent Capability）。

BRS 业务需求规格说明 · 简介

1.1 业务目的

出行运营企业需在限定 ODD 部署 L4 无人车队以降低人工驾驶成本、提升运营安全与准点率。传统机械 / 液压底盘无法直接接收电子指令，也不具备双冗余与故障降级能力，无法支撑「驾驶员缺失」场景。本业务构建标准化、可跨车型复用的线控底盘平台，作为整车厂与自动驾驶公司之间的通用执行底座，缩短新车型开发周期、降低单车成本。

1.2 业务范围

  • 业务域：自动驾驶车辆底盘开发与供应链业务域
  • 业务活动：需求定义、开发验证、量产交付、在役运维与 OTA 升级；覆盖 OEM、AD 供应商、零部件 Tier1 三方协同
  • 系统范围：线控底盘平台（含 6 大子系统）；不含感知 / 决策算法、车身内外饰，通过标准车载接口交互

1.3 业务概况

上游为 OEM 整车项目与 AD 公司自动驾驶栈；中游为本线控底盘平台；下游为充电运维场站与云控监控平台。外部监管包括 GB 自动驾驶相关标准、ISO 26262、ISO 21448 SOTIF、UN R155/R156 网络安全与软件升级。

1.4 关键定义

  • 线控（By-wire）：以电信号代替机械 / 液压连接传递控制指令
  • ODD：设计运行范围（Operational Design Domain）
  • EMB：电子机械制动（Electro-Mechanical Brake）
  • ConOps / OpsCon：运营概念 / 运行概念

3.1 业务环境

外部：L4 政策试点扩围、Robotaxi 商业化提速，线控底盘成为强制性技术门槛。

Part 3 · 作业 2 BRS / ConOps

ConOps 运营概念 站在运营企业视角

运营政策与约束

  • 仅在已公示 ODD（城市核心区、指定天气与光照）内开放付费载人
  • 每 10 台车配置 1 名远程安全员，7×24 小时值班
  • 任何 ASIL-D 故障车辆必须立即退出运营队列

系统描述

线控底盘平台作为整车「执行底座」，向上提供标准横纵向控制接口，向下驱动转向 / 制动 / 驱动 / 悬架执行器，并自带冗余与安全监控。

运行模式

M1 全自动 / M2 远程接管 / M3 最小风险 / M4 维保，状态机详见讲者 4 部分。

用户类型

乘客（无驾驶权）、远程安全员、维保技师、OEM / AD 开发工程师。

支持环境

云控平台 + 高精地图 + V2X 路侧单元 + 充换电站 + 移动维保车队。

ConOps vs OpsCon：ConOps 在组织 / 体系层面描述「系统将如何被用来做生意」，面向多系统组合的体系，描述多对多交互；OpsCon 针对车辆 / 系统本身，描述一次具体任务中底盘如何动作（见讲者 4）。

Part 6 · 安全分析（作业 3 下）

STPA 系统理论过程分析

分析思路：STPA 把安全视为控制问题——危险来自「不恰当的控制动作」，而非单一零部件失效。先建立控制结构，再识别不安全控制动作（UCA），由 UCA 导出安全需求，最后落实为安全架构机制。

系统级危险（Hazard）

H-1转向失控 / 转向失效：偏离车道、冲出道路
H-2制动失效或误制动：无法减速碰撞 / 非预期制动被追尾
H-3驱动扭矩失控：非预期加速、碰撞或甩尾
H-4人机 / 多域指令冲突：控制混乱、交接阶跃扰动
H-5通信丢失 / 超时：依据过期指令执行
H-6电源失效：执行丧失、车辆失控
H-7车辆失稳：侧滑 / 甩尾 / 侧翻

不安全控制动作（UCA）四类情形

  • 未提供必要动作：避障 / 碰撞风险下未提供制动控制动作
  • 提供不安全动作：过大 / 错误方向转角；非预期制动；非预期或超限驱动扭矩
  • 时机不当：自动 / 手动切换时机或融合不当，产生指令冲突阶跃；通信超时后仍按旧指令输出
  • 持续 / 停止不当：降级后误提前恢复全功能；制动 / 转向动作卡滞不解除

T4 横向邻车道有社会车辆，不具备安全变道条件转向保持本车道，禁止侵入邻车道；确认可控避让空间时按避让轨迹跟踪
T5 停车 / MRM前车静止停稳；或制动能力不足、风险未解除EPB 夹紧；主通道异常则备份投入；风险无法消除触发 MRM：双闪、靠边、上报云控

成功判据：无追尾 / 刮蹭；减速度跟踪误差 ≤ 0.05 g，jerk ≤ 2.5 m/s³；横向车道偏离 ≤ 0.2 m；任一链路异常 200 ms 内进入降级并可安全停车；全过程状态、故障与动作记录可追溯。

预防

冗余设计、边界校验、ODD 约束与场景库验证，使风险场景尽量不进入执行环节。

检测与降级

独立监控器发现异常后隔离故障通道，按「限制功能 → 限速蠕行 → MRM 靠边停车」分级处置。

兜底

备份链路保证最小转向与制动；MRM 停车、双闪、上报；全过程数据可追溯，支撑 FMEA / FTA 与场景补充。
