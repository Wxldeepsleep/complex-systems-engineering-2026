01

任务

Mission

该层核心追问：为什么需要它？系统存在的根本目的与价值命题是什么。

支撑 L3 及以上高阶自动驾驶的规模化落地。

精准执行

无失真指令落地

将智驾域决策指令（目标加速度、目标转角、目标姿态）准确转化为车辆物理运动。

快速响应

高控制带宽

缩短从决策发出到车身响应的时延，满足高速工况下的实时控制要求。

冗余可靠

单点失效可降级

在传感器、执行器或通信链路故障时，仍保证最低可接受的操控能力与安全停车能力。

人机共驾

接管平滑切换

在接管瞬间实现人机指令平滑切换，避免执行端产生阶跃扰动。

任务层判断：线控底盘存在的意义，不是把机械连接换成电线，而是让车辆执行端从「人控机械」变为可编程、可冗余、可诊断的执行平台，从而成为自动驾驶闭环中可被信任的一环。
02

体系

System of Systems

该层核心追问：它在哪个更大的整体中发挥作用？

智能汽车技术体系（车端技术集群）。

体系成员职责与线控底盘的接口关系
环境感知体系激光雷达、摄像头、毫米波雷达融合识别提供目标轨迹与障碍物信息（间接关联）
智能决策规划体系路径规划、行为决策、轨迹生成直接下达控制指令
线控底盘执行体系纵向 / 横向 / 垂向执行控制分析主体，指令接收端
智能座舱体系人机交互、状态呈现、接管请求交互层，提供接管信号
车路协同体系 V2X车-路-云信息交互提供超视距信息，扩展感知边界
云端数据与 OTA 体系数据回传、模型迭代、功能升级支撑执行能力持续演进
SoS 层关键特征：各成员系统原本可独立运行、独立演进，通过标准化接口耦合为整体；高阶自动驾驶这一整体能力无法由任何单一成员实现，属于涌现能力（Emergent Capability）。
03

整机

Vehicles

该层核心追问：它依附于什么实体？受什么约束？

智能驾驶整车（Vehicle Platform）。

机械载体

结构与几何边界

车身结构、悬架几何、轮距轴距、质心位置，决定执行能力的物理边界。

能量载体

供电与功率预算

高压 / 低压供电网络，决定执行器的功率可用性与功耗预算。

信息载体

车载网络架构

CAN / CAN FD / 车载以太网 / FlexRay，决定指令传输的带宽与时延。

热与空间

布置约束

冷却能力、安装空间、重量分配，约束执行器的选型与布置。

在整机层级看线控底盘，关注的是接口与包络：安装边界、供电能力、通信带宽、功能安全等级（ASIL）以及整车 E/E 架构中的位置。
04

系统

Systems（分析主体）

该层核心追问：它完成什么完整功能？

线控底盘系统：接收上层智驾域控制器的运动指令，完成车辆纵向、横向、垂向三个自由度的解耦控制，并向整车反馈执行状态。

输入

上层指令

目标加速度、目标前轮转角、目标横摆角速度、目标车身高度 / 阻尼、模式切换指令、故障诊断请求。

输出

执行反馈

实际加速度、实际转角、实际横摆响应、车身姿态、执行器状态与健康度、故障码。

约束

安全与实时性

功能安全 ISO 26262、预期功能安全 ISO 21448、信息安全 ISO/SAE 21434，控制周期毫秒级。

核心特性内涵
解耦纵向、横向、垂向动力学解耦，避免执行动作相互干扰。
冗余双电源、双通信、双执行链路，单点失效可降级运行。
可观测全链路状态可测、可诊断、可标定。
可编程通过软件定义执行特性：响应速度、阻尼特性、路感反馈。
05

子系统

Sub-systems

该层核心追问：功能由哪几块分头承担？

五大执行子系统 + 一个控制中枢。

子系统英文 / 缩写控制自由度核心职责
线控制动系统EHB / EMB / ECB纵向减速电控建压与制动力分配，支持能量回收协调。
线控转向系统SBW横向取消机械转向柱，电控转角与路感模拟。
线控驱动系统e-Powertrain Control纵向加速电机转矩请求响应与扭矩矢量分配。
线控悬架系统CDC / ECAS / 主动悬架垂向车身高度、阻尼、侧倾 / 俯仰姿态控制。
底盘域控制器CDC / VDC全局协调多子系统指令仲裁、横纵垂协同、故障降级策略。
底盘域控制器在 E/E 架构演进中承担从分布式 ECU 向中央计算 + 区域控制过渡的关键角色，是系统级协同的物理落点。
06

模块

Modules

该层核心追问：最小可独立设计、制造、验证的单元是什么？

线控制动系统

模块功能
制动执行电机模块驱动建压机构，提供制动液压 / 机械力。
液压控制单元模块阀体、泵、蓄能器，实现压力精确调节。
踏板解耦与模拟模块踏板与液压解耦，提供脚感模拟。
轮速与压力传感模块提供滑移率与压力闭环反馈。
冗余制动模块独立供电与独立控制链路，主系统失效时接管。
制动控制器模块执行制动控制算法、ABS / ESC 逻辑。

线控转向系统

模块功能
转向执行电机模块驱动转向齿条 / 转向器输出转角。
路感反馈电机模块向方向盘施加模拟反馈力矩。
转角与扭矩传感模块采集方向盘角度、扭矩、齿条位移。
转向传动机构模块齿轮齿条 / 滚珠丝杠，将旋转转为直线运动。
冗余电源与通信模块双绕组电机、双路通信，保证失效可转。
转向控制器模块转角闭环、回正控制、失效降级策略。

底盘域控制器

模块功能
主控 SoC / MCU 模块运行车辆动力学协同控制算法。
车载以太网 / CAN 通信模块与智驾域、各执行子系统通信。
电源管理与看门狗模块供电监控、程序跑飞复位。
安全监控模块（Safety MCU）独立校核主控输出，实现 ASIL-D 安全机制。
执行器驱动接口模块输出 PWM / 电流指令至各执行器。

08

关键结论

Takeaways
01

层级定位确定：线控底盘是 Systems 层级的执行域系统，不是整机也不是单一子系统；其跨功能集成属性是判定为系统层的关键依据。

02

任务决定形态：线控底盘的冗余架构、通信拓扑与控制周期，由高阶自动驾驶的安全冗余要求反向约束，而非技术偏好决定。

03

SoS 的涌现性：高阶自动驾驶能力不属于任何一个成员系统，只在体系协同中出现，这是复杂系统区别于简单系统的本质特征。

04

分解的收敛性：从 Mission 到 Modules 的六层分解，每一层都可独立定义接口与验收标准，这正是复杂系统工程可管理性的来源。

05

向下分解的边界：模块层是可独立设计、制造、验证的最小单元；再向下即进入元器件层，不再属于系统工程的分析范畴。
