02

初始系统架构

依据第 5.2 节系统架构定义过程：架构是系统在其环境中的基本概念，定义系统的结构、行为与不同视角的概念模型。初始架构从功能、逻辑、物理、接口四个视图描述「由哪些元素、如何互连来满足系统需求」，不深入具体零部件设计。

架构设计原则 Architecture Principles

  • 安全优先：安全相关功能独立设计、独立监控，输出先校验后执行。
  • 冗余独立：关键转向 / 制动通路在电源、通信、控制器上相互独立，单点失效不共因。
  • 解耦协同：纵向 / 横向 / 垂向控制解耦，由域控统一协调，避免执行动作互相干扰。
  • 可观测可编程：全链路状态可测、可诊断，执行特性由软件定义、可标定迭代。
  • 平台可演进：预留向域集中 / 中央计算 + 区域控制架构演进的接口与算力。

2.2 逻辑架构 控制闭环与逻辑元素

逻辑架构描述功能如何在逻辑元素间流动，形成「目标 → 协调算法 → 执行 → 车辆对象 → 状态估计 → 反馈」的闭环；逻辑元素与物理实现解耦：

LE-1指令解析逻辑元素

接收 F1 两路输入，完成格式解析、权限判定与合法性校验，输出统一内部目标量。

LE-2状态估计逻辑元素

融合 F2 传感信号，输出车辆状态向量与附着估计，供协调算法使用。

LE-3协调控制逻辑元素

运行车辆动力学协调控制算法（Control Algorithm），完成 F3 分配与人机仲裁。

LE-4执行驱动逻辑元素

把协调量转换为四个执行子系统的闭环驱动指令（F4）。

LE-5安全监控逻辑元素

独立校核 LE-3 输出与通路健康，触发冗余切换、降级与告警（F6）。

LE-6车辆过程模型

被控对象模型（Process Model）：执行器 + 整车动力学 + 轮胎路面，反馈状态给 LE-2。

逻辑闭环：LE-1 → LE-3（目标）→ LE-4 → LE-6（车辆）→ LE-2（状态估计）→ 回 LE-3 形成反馈；LE-5 旁路监控整条链路。该闭环即第 03 章控制框图的内部展开。

2.5 备选架构与权衡 Architecture Trade-off

方案描述优点局限结论
A分布式 ECU 各自独立控制技术成熟、单点改动影响小横纵协同弱、冗余与仲裁分散、线束复杂不满足高阶智驾协同要求
B底盘域控制器集中协调（本方案）统一仲裁与协调、冗余集中设计、软件可迭代域控本身需高可靠与安全监控选用：匹配平台需求与演进路线
C区域控制器直接执行（中央计算 + 区域）线束最精简、面向远期 E/E 架构当前供应链与成熟度不足预留接口，作为演进方向
权衡依据：安全（冗余独立性）、协同（横纵垂统一分配）、成本（平台复用）、可演进（接口预留）四项准则综合评分，方案 B 胜出；域控内部以「主控 + 独立 Safety MCU」应对自身可靠性风险。
